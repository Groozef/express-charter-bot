# Hot Tours Relay Bot

Бот-посредник: слушает "горящие туры" в чужом канале-источнике и ретранслирует их в наш канал **без изменения цены и текста**. Единственная правка — ссылка WhatsApp из поста помечается скрытой меткой, чтобы источник видел, что заявка пришла из нашего канала (реферальная модель: без наценки, без приёма оплаты, зарабатываем на комиссии/агентских от источника).

## Как это работает

Bot API не может читать посты из канала, в котором бот не состоит и не является админом. Поэтому используется связка из двух Telegram-клиентов:

1. **Юзербот (MTProto, библиотека `telegram`/GramJS)** — логинится под обычным Telegram-аккаунтом, который **обязательно должен быть подписан на канал-источник**. Слушает новые посты в реальном времени (`NewMessage`).
2. **Bot API (Telegraf)** — публикует готовое сообщение в наш канал, где бот добавлен админом.

Пайплайн между ними (в NestJS всё раздельными модулями, но развёртывается одним процессом/контейнером):

```
source channel  →  UserbotModule  →  event bus  →  PipelineService
                                                        ├─ RawLogService      (лог оригинала в файл + консоль)
                                                        ├─ TransformerService (метка wa.me-ссылки + подпись-инструкция)
                                                        ├─ StateService       (дедуп по id сообщения, переживает рестарт)
                                                        └─ PublisherService   (публикация в целевой канал через Bot API)
```

Архитектура нарочно простая (монолит из модулей), но модули изолированы — если объём вырастет (несколько источников, очередь, БД вместо файлов), каждый блок можно вынести в отдельный сервис без переписывания логики.

## Что именно делает TransformerService

Пост публикуется практически один в один, кроме трёх точечных правок (`src/transformer/transformer.service.ts`):

1. **Метка на ссылке WhatsApp.** К `wa.me/<номер>` добавляется `?text=...` с заранее заданным сообщением ("Здравствуйте! Пишу с канала Express Charter KZ..."). При переходе клиента в WhatsApp это сообщение уже стоит в поле ввода — источник видит, что заявка от нас, даже если клиент ничего не печатал сам. Метка живёт в самой ссылке, а не в тексте поста — случайно её не сотрёшь.
2. **Ссылка спрятана за читаемым текстом.** Из-за `?text=...` голая ссылка превращается в длинное полотно из `%D0%97...`. Чтобы это не пугало клиентов и антивирусы (сторонние сокращатели типа is.gd/da.gd массово в блок-листах как "фишинг-риск" — пробовали, не пошло), используется HTML-разметка Telegram: `<a href="длинная-ссылка">📲 Писать со Скрином (WhatsApp)</a>` + `parse_mode: 'HTML'` при отправке. Ссылка настоящая (`wa.me`, домен WhatsApp/Meta), просто визуально спрятана за кнопкой-текстом. Из-за HTML-режима весь остальной текст поста экранируется (`&`, `<`, `>`), чтобы случайный спецсимвол не сломал парсинг у Telegram.
3. **Подпись-напоминание** добавляется прямо перед строкой со ссылкой (`POST_FOOTER_TEXT`) — коротко про два обязательных условия заявки (скриншот + не удалять авто-сообщение), видно сразу в посте, а не только после перехода в WhatsApp.

Дополнительно: строка с рекламой чужого канала/сайта источника (например, "✅Каналы по Турам и Авиа: www.AviaTravel.kz/kanal") вырезается — определяется по домену, отличному от `wa.me`, либо по слову "канал" в строке (для варианта, когда ссылка идёт отдельной строкой от подписи).

Если у источника контакт окажется ботом (`@something_bot`), а не WhatsApp-номером — там есть более надёжный вариант метки через `?start=` (Telegram deep link, его нельзя стереть вообще, в отличие от предзаполненного текста WhatsApp) — под это нужно менять логику отдельно.

## Настройка

### 1. Данные окружения

```bash
cp .env.example .env
```

Заполните:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather). Этого бота добавьте **админом** в целевой канал.
- `TG_API_ID` / `TG_API_HASH` — получить на https://my.telegram.org (API Development Tools) под аккаунтом, который подписан на канал-источник.
- `SOURCE_CHANNEL_ID`, `TARGET_CHANNEL_ID` — ID каналов (формат `-100…`).
- `WHATSAPP_TRACKING_TEXT` — сообщение, которое автоматически подставится в WhatsApp при переходе по ссылке.
- `WHATSAPP_LINK_LABEL` — видимый текст кнопки-ссылки (по умолчанию "📲 Писать со Скрином (WhatsApp)").
- `POST_FOOTER_TEXT` — короткая подпись-напоминание перед ссылкой в каждом посте.

### 2. Логин юзербота (один раз)

```bash
npm install
npm run generate:session
```

Скрипт спросит номер телефона, код из Telegram и, если включена, 2FA-пароль. В конце выведет строку — вставьте её в `.env` как `TG_SESSION`. Хранить эту строку нужно так же секретно, как пароль от аккаунта — она даёт полный доступ к нему.

### 3. Запуск

Через Docker (рекомендуется для прод):

```bash
docker compose up -d --build
```

**Важно:** `--build` нужен каждый раз, когда меняется код (не только `.env`) — иначе контейнер продолжит работать на старом образе. Если менялся только `.env` — достаточно `docker compose restart bot`.

Локально для разработки:

```bash
npm run start:dev
```

Нельзя запускать Docker и локальный процесс одновременно — оба будут слушать один и тот же юзербот-аккаунт и задублируют посты. Перед локальным запуском: `docker compose stop bot`.

Логи оригинальных сообщений пишутся в `logs/raw-messages.log` (JSON lines) и дублируются в консоль. Состояние (id уже опубликованных сообщений) — в `data/state.json`, оба каталога монтируются как volume в docker-compose, чтобы переживать пересоздание контейнера.

## Вспомогательные скрипты (`scripts/`)

Все запускаются напрямую через `ts-node`, читают тот же `.env`. Перед запуском любого из них — остановите живой контейнер (`docker compose stop bot`), чтобы не было двух активных подключений юзербота одновременно.

- **`npm run backfill -- N`** — забирает последние N сообщений источника (от старых к новым) и публикует через тот же пайплайн. Полезно, чтобы заполнить пустой канал или проверить логику без ожидания нового поста. Дублей с live-ботом не будет.
- **`npx ts-node scripts/purge-target.ts [до какого ID]`** — Bot API не даёт получить историю канала, поэтому скрипт перебирает ID сообщений подряд (по умолчанию 1..300) и удаляет каждое, что нашлось. Несуществующие ID просто пропускаются. Используется для полной очистки канала во время тестов.
- **`npx ts-node scripts/post-instructions.ts`** — публикует и закрепляет в канале сообщение с инструкцией для клиентов (2 обязательных пункта заявки). Текст инструкции зашит прямо в скрипте — поменять можно там же.

## Устойчивость юзербота

Соединение MTProto (GramJS) по наблюдениям иногда рвётся по сетевым причинам (провайдер/VPN у казахстанских/российских ISP периодически режет прямые MTProto-соединения на десятки минут), и внутренний реконнект библиотеки не всегда надёжен — на практике встречалось зависание без единой попытки почти на 2 часа. Поэтому в `UserbotService` есть два независимых предохранителя:

1. **Таймаут первого подключения** (60 сек) — если `connect()` не отработал за это время, процесс завершается сам.
2. **"Сторож" после подключения** — раз в 30 сек проверяет `client.connected`; если 3 проверки подряд (~90 сек) связи нет, процесс тоже завершается.

В обоих случаях `restart: unless-stopped` в docker-compose поднимает контейнер заново — на практике свежий запуск всегда подключается быстро (доли секунды). Логи о срабатывании — `Юзербот не на связи` / `Соединение не восстановилось — перезапускаю процесс`.

Радикальное решение той же проблемы — разворачивать бота на VPS за пределами РФ/РК (например, Hetzner/DigitalOcean/Vultr в Европе), тогда локальных блокировок провайдера просто нет.

## Известные ограничения

- Альбомы (несколько фото в одном посте) не поддержаны — обрабатывается первое фото/документ + текст. При необходимости легко добавить группировку по `grouped_id` из GramJS.
- Юзербот-аккаунт должен оставаться подписанным на канал-источник, иначе перестанет получать посты.
- Пока перезапускается процесс (после разрыва связи) — сообщения, пришедшие в этот момент, не долетают и не восстанавливаются задним числом. Можно вручную прогнать `npm run backfill -- N`, если что-то пропустили.
- Бот работает только пока запущен Docker/процесс. Если гоняете локально на своём ПК — при выключении/сне компьютера или закрытии Docker Desktop бот останавливается. Для работы 24/7 нужен VPS.
- Метка через `?text=` в WhatsApp — это только предзаполнение поля ввода: если клиент намеренно сотрёт текст перед отправкой, метка потеряется (в отличие от Telegram bot deep link `?start=`, который стереть нельзя).
