# Hot Tours Relay Bot

Бот-посредник: читает "горящие туры" из чужого канала-источника и публикует их в ваш канал с наценкой (по умолчанию +15%) и своими контактами вместо оригинальных.

## Как это работает

Bot API не может читать посты из канала, в котором бот не состоит и не является админом. Поэтому используется связка из двух Telegram-клиентов:

1. **Юзербот (MTProto, библиотека `telegram`/GramJS)** — логинится под обычным Telegram-аккаунтом, который **обязательно должен быть подписан на канал-источник**. Слушает новые посты в реальном времени (`NewMessage`).
2. **Bot API (Telegraf)** — публикует готовое сообщение в ваш канал, где бот добавлен админом.

Пайплайн между ними (в NestJS все раздельными модулями, но развёртывается одним процессом/контейнером):

```
source channel  →  UserbotModule  →  event bus  →  PipelineService
                                                        ├─ RawLogService   (лог оригинала в файл + консоль)
                                                        ├─ TransformerService (цена +15%, замена контактов)
                                                        ├─ StateService    (дедуп по id сообщения, переживает рестарт)
                                                        └─ PublisherService (публикация в целевой канал через Bot API)
```

Архитектура нарочно простая (монолит из модулей), но модули изолированы — если объём вырастет (несколько источников, очередь, БД вместо файлов), каждый блок можно вынести в отдельный сервис без переписывания логики.

## Настройка

### 1. Данные окружения

```bash
cp .env.example .env
```

Заполните:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather). Этого бота добавьте **админом** в целевой канал `-1004360728939`.
- `TG_API_ID` / `TG_API_HASH` — получить на https://my.telegram.org (Api Development Tools) под аккаунтом, который подписан на канал-источник `-1001534797825`.
- `SOURCE_CHANNEL_ID`, `TARGET_CHANNEL_ID` — уже проставлены под ваши каналы.
- `CONTACT_TELEGRAM`, `CONTACT_PHONE`, `CONTACT_WHATSAPP` — контакты, которые попадут в каждый пост вместо оригинальных. Меняются в любой момент простым редактированием `.env` и рестартом контейнера.
- `MARKUP_PERCENT` — наценка, по умолчанию 15.

### 2. Логин юзербота (один раз)

```bash
npm install
npm run generate:session
```

Скрипт спросит номер телефона, код из Telegram и, если включена, 2FA-пароль. В конце выведет строку — вставьте её в `.env` как `TG_SESSION`. Хранить эту строку нужно так же секретно, как пароль от аккаунта — она даёт полный доступ к нему.

### 3. Запуск

Через Docker (рекомендуется для прод):

```bash
docker compose up -d --build
```

**Важно:** `--build` нужен каждый раз, когда меняется код (не только `.env`) — иначе контейнер продолжит работать на старом образе. Если менялся только `.env` — достаточно `docker compose restart bot`.

Локально для разработки:

```bash
npm run start:dev
```

Нельзя запускать Docker и локальный процесс одновременно — оба будут слушать один и тот же юзербот-аккаунт и задублируют посты. Перед локальным запуском: `docker compose stop bot`.

Логи оригинальных сообщений пишутся в `logs/raw-messages.log` (JSON lines) и дублируются в консоль. Состояние (id уже опубликованных сообщений) — в `data/state.json`, оба каталога монтируются как volume в docker-compose, чтобы переживать пересоздание контейнера.

### 4. Разовое заполнение канала старыми постами

Чтобы канал не был пустым при старте (или чтобы проверить пайплайн без ожидания нового поста в источнике):

```bash
npm run backfill -- 20
```

Заберёт последние 20 сообщений из канала-источника (от старых к новым), прогонит через ту же наценку/замену контактов и опубликует с паузой ~2.5 сек между постами. Одноразовый скрипт, с live-пайплайном не пересекается — дублей не будет.

## Формат цен канала-источника

Парсер (`src/transformer/transformer.service.ts`) настроен и протестирован на реальном формате конкретного канала-источника (авиабилеты/туры из Казахстана):

- Цены пишутся **без валюты**, с пробелом как разделителем тысяч: `60 000🔥`, `140 000(6)`. К таким ценам после наценки добавляется суффикс `KZT`.
- Цены с явной валютой (`100 000 тг`, `$100`) тоже поддерживаются и распознаются отдельно.
- Даты (`02.07`), время (`03:20-06:50`), вес багажа (`23 kg`) и число пассажиров в скобках (`(6)`) не путаются с ценой и не трогаются.
- Строки со ссылками (`wa.me/...`, `www.site.kz/...`), юзернеймами (`@username`), номерами телефонов и словами-триггерами (whatsapp, пиши, звони, контакт, канал и т.п.) вырезаются целиком; если на той же строке есть цена — вырезается только ссылка/юзернейм, сама строка с ценой остаётся.

Если формат источника изменится или добавится второй источник с другим оформлением — регэкспы в этом файле нужно будет донастроить под новый формат (лучше всего — на реальных примерах сообщений).

## Устойчивость юзербота

Соединение MTProto (GramJS) по наблюдениям иногда рвётся по сетевым причинам (провайдер/VPN), и внутренний реконнект библиотеки не всегда надёжен — на практике встречалось зависание без единой попытки почти на 2 часа. Поэтому в `UserbotService` есть два независимых предохранителя:

1. **Таймаут первого подключения** (60 сек) — если `connect()` не отработал за это время, процесс завершается сам.
2. **"Сторож" после подключения** — раз в 30 сек проверяет `client.connected`; если 3 проверки подряд (~90 сек) связи нет, процесс тоже завершается.

В обоих случаях `restart: unless-stopped` в docker-compose поднимает контейнер заново — на практике свежий запуск всегда подключается быстро (доли секунды). Логи о срабатывании — `Юзербот не на связи` / `Соединение не восстановилось — перезапускаю процесс`.

## Известные ограничения

- Альбомы (несколько фото в одном посте) не поддержаны — обрабатывается первое фото/документ + текст. При необходимости легко добавить группировку по `grouped_id` из GramJS.
- Юзербот-аккаунт должен оставаться подписанным на канал-источник, иначе перестанет получать посты.
- Пока перезапускается процесс (после разрыва связи) — сообщения, пришедшие в этот момент, не долетают и не восстанавливаются задним числом. Можно вручную прогнать `npm run backfill -- N`, если что-то пропустили.
- Бот работает только пока запущен Docker/процесс. Если гоняете локально на своём ПК — при выключении/сне компьютера бот останавливается. Для работы 24/7 нужен VPS.
